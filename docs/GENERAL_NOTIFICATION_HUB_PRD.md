# 桌面通用通知胶囊｜产品需求文档

状态：方案稿（用于评审与拆分开发任务）

适用平台：Windows、macOS

基线：Amazon Sales Bubble v2.5.1

定位：将现有可拖动的单颗悬浮胶囊，扩展为多个应用和服务共用的桌面通知入口。

## 1. 背景与目标

当前产品把 Amazon 当日销售额作为常驻内容，订单、退款和 Review 作为短暂事件。窗口、玻璃材质、拖动、事件队列和本地存储已经可复用，但事件校验、合并和界面文案仍绑定 Amazon 销售场景。

新产品让用户在工作时通过**一颗胶囊**感知值得处理的消息，点击后在同一应用的通知列表中回看与处理。它应允许现有 Amazon 数据源继续工作，并为其他来源提供明确、可撤销的接入方式。胶囊是轻量入口，不承担完整聊天、邮件或任务管理。

首版成功标准：

1. 用户无需连接 Amazon，也能接入一个本地来源，收到、查看、标记和清除通知。
2. 多个来源同时发消息时，胶囊仍保持单一、可读、可拖动，高频通知不会无限排队。
3. 安静时段、隐私模式和来源开关能可靠阻止不需要的弹出与敏感内容泄露。
4. 现有销售额与订单通知可作为一个来源继续使用，销售统计口径和金额动画不被通用通知逻辑改写。

## 2. 用户与使用场景

| 用户 | 主要需求 | 示例 |
| --- | --- | --- |
| 多工具办公用户 | 一眼看到真正需要处理的新消息 | 构建失败、待办到期、日程开始 |
| Amazon 卖家 | 保留销售额和订单反馈，同时接收其他工作消息 | 新订单后收到客服待回复提醒 |
| 开发者或团队管理员 | 将已有脚本、服务接入胶囊 | 本地任务完成或监控告警 |

典型路径：来源接入 → 新消息在胶囊内短暂出现 → 胶囊回到静态状态 → 点击胶囊打开通知列表 → 用户查看、执行安全操作或标记已读。

## 3. 产品原则与范围

- **一个入口**：桌面只存在一颗可拖动胶囊。通知列表是点击后打开的辅助面板，不再创建第二颗事件气泡。
- **先可控接入**：首版接收应用自身来源与用户主动授权的本地推送。读取其他软件已经交给操作系统的通知属于后续平台研究与适配，不作为首版承诺。
- **状态与事件分离**：销售额等持续状态是可选胶囊首页；通知是可回看的记录。展示过不等于已读。
- **少打断**：默认只让新通知短暂停留；低优先级消息可只增加未读数。
- **隐私优先**：来源逐个启用，内容可隐藏，本地保存有期限，关闭来源后立即停止接收。

### 3.1 首版 P0

- Windows、macOS 共用的单颗悬浮胶囊；拖动、置顶、玻璃浓度、减少动态沿用现有能力。
- 胶囊静态状态、事件展示、未读角标、通知列表、通知详情与已读/全部已读/删除。
- 现有 Amazon/GerpGo/通用 ERP 事件作为内置来源接入统一通知层；销售额仍可选为静态状态。
- 本地推送接入：仅监听 `127.0.0.1`，为每个来源单独生成访问令牌；提供接入说明和测试发送按钮。
- 来源开关、优先级映射、安静时段、隐私模式、保留期限及错误状态。
- 重复消息去重、短时间分组、队列上限、重启后的未读记录恢复。

### 3.2 后续 P1 / P2

| 阶段 | 候选能力 | 前置条件 |
| --- | --- | --- |
| P1 | 经用户授权的日历、邮件、IM、CI 等官方连接器 | 各服务的授权方式、额度、字段和退出机制单独设计 |
| P1 | 跨设备同步、来源级规则、快速回复/完成任务 | 身份体系、冲突处理及对应服务的写入权限 |
| P2 | 读取或转发系统通知中心的通知 | 分平台验证权限、可用接口、兼容性及原应用去重策略 |

首版不做全屏 Dashboard、任意屏幕抓取、自动读取其他应用窗口文本、任意命令执行、未经授权的云端汇总或手机推送。

## 4. 信息结构与界面

### 4.1 胶囊状态

| 状态 | 内容 | 行为 |
| --- | --- | --- |
| 静态 | 默认显示未读数量；用户可改为“今日销售额”或极简图标 | 1 条未读显示 `1`，99 条以上显示 `99+`；无未读时保留可点击入口 |
| 新通知 | 来源图标/名称、短标题、至多一行摘要 | 停留约 3 秒；高优先级约 5 秒；结束后回到静态状态 |
| 汇总 | `来源 · 新增 N 条`，避免连续刷屏 | 点击进入已按来源分组的列表 |
| 安静 | 保持静态内容，仅更新未读数 | 不自动播放内容和声音 |
| 异常 | 小型状态标记；详情在列表/设置中解释 | 单一来源失败不覆盖其他来源的通知 |

沿用现有固定透明宿主约 `360 × 100`；可见胶囊维持当前紧凑形态，静态约 `220 × 56`，事件最大约 `320 × 72`。内容溢出时截断，完整内容进通知列表。切换事件时不改变宿主窗口边界，不出现胶囊外色块或方形阴影。

颜色仅用于区分需要注意的程度：普通中性、成功轻绿、警告琥珀、紧急柔和红。颜色不能成为唯一信号，必须同时有文字或图标。玻璃浓度调节应保证浅色和深色桌面上文字可读。

### 4.2 点击与拖动

- 单击胶囊：打开或关闭通知列表；单击当前通知时定位到对应记录。
- 按住并移动：拖动胶囊，松开后保存位置；移动超过拖动阈值时不触发单击。
- 右键：打开隐藏胶囊、安静 1 小时、设置、退出等菜单。
- 列表失焦后可关闭；再次单击胶囊恢复。窗口位置跟随胶囊，并受屏幕工作区约束。
- 键盘可通过通知列表完成导航、查看、标记已读和关闭；减少动态开启时取消位移与弹跳动画。

### 4.3 通知列表

列表提供“全部 / 未读”、来源筛选和按时间倒序排列。每行包含来源、标题、时间、简短正文、优先级及已读状态。详情展示完整正文和来源提供的安全操作。支持单条标记已读、删除、全部标记已读和清空已读。空列表、离线、来源失效均有简短明确的状态说明。

**阅读语义**：胶囊播放不自动标记已读；用户打开通知详情或手动标记时才变已读。删除不影响外部应用中的原消息。

## 5. 统一通知协议

销售事件先映射为通用通知，再交给展示调度器。通用通知不包含销售额计算；销售汇总和货币换算仍留在现有业务域。

```json
{
  "id": "build-4821",
  "sourceId": "local-ci",
  "occurredAt": "2026-10-08T09:30:00Z",
  "category": "task",
  "priority": "normal",
  "title": "构建已完成",
  "body": "桌面客户端构建成功",
  "groupKey": "desktop-client-build",
  "expiresAt": null,
  "actions": [
    { "id": "open", "label": "查看详情", "kind": "open-url", "target": "https://example.com/build/4821" }
  ]
}
```

| 字段 | 规则 |
| --- | --- |
| `id`、`sourceId` | 必填；同一来源内稳定唯一；以二者组合作为去重键 |
| `occurredAt` | 必填 ISO 8601 时间；保留来源时间与本机接收时间 |
| `category` | `commerce`、`message`、`task`、`calendar`、`system`、`other` |
| `priority` | `low`、`normal`、`high`；来源可申请，用户规则可以降级或静默 |
| `title`、`body` | 标题必填；限制长度，纯文本处理，禁止 HTML 注入 |
| `groupKey` | 可选；只合并相同来源且同组的短时间消息 |
| `expiresAt` | 可选；过期消息不再弹出，是否保留在历史中由保留策略决定 |
| `actions` | 可选；首版仅支持经过校验的 HTTPS 链接或应用内详情；不执行任意脚本、命令或自定义协议 |

来源配置包括显示名、图标、启用状态、令牌、默认优先级、是否自动弹出、是否显示内容及最后一次接收时间。应用生成 `sourceId`，本地接口的令牌只能写入该来源，不能读取通知历史或其他来源配置。

## 6. 接入、调度与生命周期

### 6.1 本地接入

用户在“来源”页新增来源后，应用显示本机地址、令牌和 JSON 示例；令牌只显示一次，可单独轮换或撤销。接口只接收本机回环连接；请求须携带来源令牌，并限制请求体大小、发送频率和字段长度。接口不开放通配 CORS，拒绝非预期网页来源。非法请求明确报错但不写入通知库。配置页面提供“发送测试通知”，使用户无需编写脚本即可核对胶囊和列表。

首版可以先提供单条通知写入接口；批量、远程 Webhook 和第三方云回调需要独立鉴权及网络安全设计后再开放。应用退出或来源关闭时，本地监听立即停止。

### 6.2 调度规则

1. 消息入库后按 `sourceId + id` 去重。相同 ID 的新版本可以更新详情，但默认不再次弹出；来源显式增加版本号才视为新通知。
2. `high` 优先于 `normal`，`low` 默认只进列表和未读数；同级按接收时间排序。正在显示的消息不中途消失，下一条再按优先级选择。
3. 同来源、同 `groupKey` 的消息在约 3 秒窗口内合并；队列超过 5 条时转为来源汇总。不同来源的高优先级消息不能被低优先级洪峰挤掉。
4. 安静时段或手动静音时只入库和更新未读数；用户可单独允许某来源的高优先级消息突破静音，默认关闭。
5. 休眠恢复、首次连接或重连时先建立基线：旧消息进入列表但不逐条弹出；仅对基线之后的新消息播报。
6. 展示超时后回到用户选定的静态内容。若静态内容为销售额，订单/退款事件沿用现有“先事件、后金额变化”动画；其他通知不改变销售额。

### 6.3 本地数据与隐私

通知记录和已读状态保存在本机 SQLite，按来源隔离；默认保留 7 天，可选 1、7、30 天。过期记录定期清理。令牌使用系统安全存储能力，日志只记录来源 ID、错误类别和时间，不记录令牌或通知正文。隐私模式开启后，胶囊只显示来源和“新通知”，列表内容需要用户主动打开才呈现。用户可清除单个来源历史或全部历史。

## 7. 设置结构

设置页收敛为四组：

1. **外观**：静态内容（未读 / 今日销售额 / 图标）、玻璃浓度、置顶、减少动态、胶囊位置重置。
2. **来源**：Amazon/ERP 内置来源、本地来源列表、新增/停用/删除、发送测试消息、令牌轮换。
3. **通知**：各来源的弹出开关、优先级、安静时段、隐私模式、数据保留和清理。
4. **关于**：版本、诊断信息及接入文档。

首次启动展示三步引导：选择静态内容 → 启用现有 Amazon 来源或创建本地来源 → 发送测试通知。旧版本升级时沿用用户当前的销售额首页和原有店铺/凭证设置，不强制重新授权。

## 8. 技术改造边界

| 现有模块 | 改造方向 |
| --- | --- |
| `core/engine.*`、`core/presentation.mjs` | 保留销售事件处理；新增独立的通用通知校验、持久化和调度器，避免让非销售消息经过金额逻辑 |
| `core/store.cjs` | 新增 `notification_sources`、`notifications`、`notification_state` 表和迁移；旧销售表保持原语义 |
| `electron/application.cjs` | 增加本地接入服务、来源管理、通知列表 IPC 与窗口状态广播；保持单个胶囊窗口 |
| `src/App.jsx` | 将品牌固定内容改为可配置静态内容，增加通用通知模板和列表视图 |
| `electron/gerpgo/*`、`electron/custom/*` | 通过适配层输出通知，同时继续负责原有销售统计 |

所有外部数据先在主进程校验和清洗，渲染进程只接收展示所需字段。本地接入服务与设置页分别授予最少能力；不把任意 URL 或文件路径直接交给窗口导航。

## 9. 验收标准

- 两个独立本地来源发送 10 条不同消息后，数据库和列表均保留正确来源、顺序、未读状态；重启后状态不丢失。
- 同一来源重复发送同一 `id` 不重复弹出；另一个来源使用相同 `id` 仍是新通知。
- 连续 20 条低优先级消息被合并/静默后，高优先级消息仍能在当前展示结束后进入胶囊；队列有上限。
- 胶囊从通知内容回到静态状态时没有窗口边界变化、外部色块或误触拖动；Windows 和 macOS 分别验证。
- 安静时段、隐私模式、关闭来源、撤销令牌和保留期清理均有可重复的行为测试。
- Amazon 新订单仍先展示 SKU 与金额，再回到已更新的销售总额；普通通知不会改变销售额。
- 离线或来源错误不阻塞其他来源；应用恢复后不把积压历史逐条弹出。
- 产品文档和设置 UI 明确说明首版只聚合已接入来源，系统通知读取列为后续能力。

## 10. 待评审决策

以下选择不阻挡 P0 架构设计，但在视觉稿和开发排期前需要确定：

1. 产品是否更名为通用品牌；若更名，迁移现有用户数据目录与应用标识需单独设计。
2. 首次安装的默认静态内容：本稿建议“未读数量”，升级用户继续使用“今日销售额”。
3. 首个官方第三方连接器的优先级；建议根据目标用户群在日历、邮件和团队协作工具中选择一个进行 P1 验证。
