# 桌面通用通知胶囊｜产品需求文档

状态：方案稿（用于评审与拆分开发任务）

适用平台：Windows、macOS

基线：Amazon Sales Bubble v2.5.1

定位：将现有可拖动的单颗悬浮胶囊，扩展为多个应用和服务共用的桌面通知入口。

## 1. 背景与目标

当前产品把 Amazon 当日销售额作为常驻内容，订单、退款和 Review 作为短暂事件。窗口、玻璃材质、拖动、事件队列和本地存储已经可复用，但事件校验、合并和界面文案仍绑定 Amazon 销售场景。

新产品让用户在工作时通过**一颗胶囊**感知值得处理的消息，点击后在同一应用的通知列表中回看与处理。本次只设计通用通知核心和扩展能力：统一消息结构、来源标识、展示调度、存储和扩展模块生命周期。具体数据获取、认证和平台适配由未来独立模块负责。

首版成功标准：

1. 用户无需连接 Amazon，也能通过内置模拟通知验证展示、查看、标记和清除流程。
2. 多个来源同时发消息时，胶囊仍保持单一、可读、可拖动，高频通知不会无限排队。
3. 安静时段、隐私模式和来源开关能可靠阻止不需要的弹出与敏感内容泄露。
4. 通用核心具备供未来扩展模块使用的内部契约，现有销售功能的统计口径和金额动画有独立边界。

## 2. 用户与使用场景

| 用户 | 主要需求 | 示例 |
| --- | --- | --- |
| 多工具办公用户 | 一眼看到真正需要处理的新消息 | 构建失败、待办到期、日程开始 |
| Amazon 卖家 | 保留销售额和订单反馈，同时接收其他工作消息 | 新订单后收到客服待回复提醒 |
| 未来扩展模块开发者 | 复用通用通知能力 | 通过标准消息结构使用展示、去重和存储能力 |

典型路径：通用核心收到通知 → 新消息在胶囊内短暂出现 → 胶囊回到静态状态 → 点击胶囊打开通知列表 → 用户查看或标记已读。首版通过模拟数据验证此路径。

## 3. 产品原则与范围

- **一个入口**：桌面只存在一颗可拖动胶囊。通知列表是点击后打开的辅助面板，不再创建第二颗事件气泡。
- **只保留扩展能力**：本次交付内部消息契约和模块边界。具体服务、协议、授权流程及系统通知读取均不纳入本次开发。
- **状态与事件分离**：销售额等持续状态是可选胶囊首页；通知是可回看的记录。展示过不等于已读。
- **少打断**：默认只让新通知短暂停留；低优先级消息可只增加未读数。
- **隐私优先**：来源逐个启用，内容可隐藏，本地保存有期限，关闭来源后立即停止接收。

### 3.1 首版 P0

- Windows、macOS 共用的单颗悬浮胶囊；拖动、置顶、玻璃浓度、减少动态沿用现有能力。
- 胶囊静态状态、事件展示、未读角标、通知列表、通知详情与已读/全部已读/删除。
- 通用通知内部契约、来源命名空间、模块注册/启用/停用的能力边界。
- 内置模拟通知与多来源测试样例，用于验证通知核心和界面。
- 现有销售功能与通用通知核心的兼容边界；本次不新增或重做业务适配器。
- 来源开关、优先级映射、安静时段、隐私模式、保留期限及错误状态。
- 重复消息去重、短时间分组、队列上限、重启后的未读记录恢复。

### 3.2 扩展预留

| 扩展点 | 预留能力 | 本次交付边界 |
| --- | --- | --- |
| 通知来源 | 将标准消息交给通用核心 | 内部契约与生命周期，不实现数据获取 |
| 持续状态 | 提供胶囊静态内容 | 状态描述与展示槽位，不新增业务指标 |
| 通知动作 | 声明未来可用的通知操作 | 预留动作标识和标签，本次仅支持应用内查看 |
| 连接状态 | 表达模块启用、停用、异常 | 通用状态模型，不实现账号连接和重连协议 |

本次范围明确排除：本地 HTTP 服务、REST/Webhook 接口、访问令牌和 OAuth 流程、第三方 SDK、具体平台连接器、系统通知抓取、跨设备同步、外部写入操作以及插件市场。上述能力需要后续单独提出需求。

## 4. 信息结构与界面

### 4.1 胶囊状态

| 状态 | 内容 | 行为 |
| --- | --- | --- |
| 静态 | 默认显示未读数量；用户可改为“今日销售额”或极简图标 | 1 条未读显示 `1`，99 条以上显示 `99+`；无未读时保留可点击入口 |
| 新通知 | 来源图标/名称、短标题、至多一行摘要 | 停留约 3 秒；高优先级约 5 秒；结束后回到静态状态 |
| 汇总 | `来源 · 新增 N 条`，避免连续刷屏 | 点击进入已按来源分组的列表 |
| 安静 | 保持静态内容，仅更新未读数 | 不自动播放内容和声音 |
| 异常 | 小型状态标记；详情在列表/设置中解释 | 单一来源失败不覆盖其他来源的通知 |

沿用现有固定透明宿主约 `360 × 100`；可见胶囊维持当前紧凑形态，静态约 `220 × 56`，事件最大约 `320 × 72`。内容溢出时截断，完整内容进通知列表。切换事件时不改变宿主窗口边界，不出现胶囊外色块或方形阴影。

颜色仅用于区分需要注意的程度：普通中性、成功轻绿、警告琥珀、紧急柔和红。颜色不能成为唯一信号，必须同时有文字或图标。玻璃浓度调节应保证浅色和深色桌面上文字可读。

### 4.2 点击与拖动

- 单击胶囊：打开或关闭通知列表；单击当前通知时定位到对应记录。
- 按住并移动：拖动胶囊，松开后保存位置；移动超过拖动阈值时不触发单击。
- 右键：打开隐藏胶囊、安静 1 小时、设置、退出等菜单。
- 列表失焦后可关闭；再次单击胶囊恢复。窗口位置跟随胶囊，并受屏幕工作区约束。
- 键盘可通过通知列表完成导航、查看、标记已读和关闭；减少动态开启时取消位移与弹跳动画。

### 4.3 通知列表

列表提供“全部 / 未读”、来源筛选和按时间倒序排列。每行包含来源、标题、时间、简短正文、优先级及已读状态。详情展示完整正文；来源专属操作只预留扩展位置。支持单条标记已读、删除、全部标记已读和清空已读。空列表与模块异常均有简短明确的状态说明。

**阅读语义**：胶囊播放不自动标记已读；用户打开通知详情或手动标记时才变已读。删除不影响外部应用中的原消息。

## 5. 统一通知协议

以下是进程内使用的数据契约示例，用于约束未来扩展模块提交的消息，不是对外 API。本次通过模拟消息验证。通用通知不包含销售额计算；销售汇总和货币换算仍留在现有业务域。

```json
{
  "id": "build-4821",
  "sourceId": "demo-source-a",
  "occurredAt": "2026-10-08T09:30:00Z",
  "category": "task",
  "priority": "normal",
  "title": "构建已完成",
  "body": "桌面客户端构建成功",
  "groupKey": "desktop-client-build",
  "expiresAt": null
}
```

| 字段 | 规则 |
| --- | --- |
| `id`、`sourceId` | 必填；同一来源内稳定唯一；以二者组合作为去重键 |
| `occurredAt` | 必填 ISO 8601 时间；保留来源时间与本机接收时间 |
| `category` | `commerce`、`message`、`task`、`calendar`、`system`、`other` |
| `priority` | `low`、`normal`、`high`；来源可申请，用户规则可以降级或静默 |
| `title`、`body` | 标题必填；限制长度，纯文本处理，禁止 HTML 注入 |
| `groupKey` | 可选；只合并相同来源且同组的短时间消息 |
| `expiresAt` | 可选；过期消息不再弹出，是否保留在历史中由保留策略决定 |
| `actions` | 扩展预留字段；动作标识与标签的执行语义由未来模块定义，本次只有应用内详情 |

来源描述包括唯一 `sourceId`、显示名、图标、启用状态、默认优先级、是否自动弹出、是否显示内容及最后一次消息时间。来源通过内部注册机制声明，通知核心按来源隔离记录与策略。凭证、地址、认证方式和外部 API 参数不进入通用核心。

## 6. 扩展边界、调度与生命周期

### 6.1 扩展模块能力边界

通用核心预留注册来源、接收标准消息、更新持续状态、报告模块状态、启用/停用来源的内部能力。扩展模块只提交自己命名空间内的数据；消息进入核心后统一校验、去重、入库和调度。停用来源时停止其消息展示，其他来源继续正常工作。

本次仅使用内置模拟来源验证上述契约。数据采集方式、网络协议、认证和外部操作由未来模块独立定义；文档不指定具体接口路径、端口或 SDK。扩展模块若需加载第三方代码，必须另行设计安装、授权、隔离和卸载机制。

### 6.2 调度规则

1. 消息入库后按 `sourceId + id` 去重。相同 ID 可以更新详情，但不再次弹出；独立的新事件必须使用新的 ID。
2. `high` 优先于 `normal`，`low` 默认只进列表和未读数；同级按接收时间排序。正在显示的消息不中途消失，下一条再按优先级选择。
3. 同来源、同 `groupKey` 的消息在约 3 秒窗口内合并；队列超过 5 条时转为来源汇总。不同来源的高优先级消息不能被低优先级洪峰挤掉。
4. 安静时段或手动静音时只入库和更新未读数；用户可单独允许某来源的高优先级消息突破静音，默认关闭。
5. 预留历史导入与实时消息标识：历史数据进入列表但不逐条弹出，实时消息按规则播报；本次用模拟数据验证，不实现同步或重连接口。
6. 展示超时后回到用户选定的静态内容。若静态内容为销售额，订单/退款事件沿用现有“先事件、后金额变化”动画；其他通知不改变销售额。

### 6.3 本地数据与隐私

通知记录和已读状态保存在本机 SQLite，按来源隔离；默认保留 7 天，可选 1、7、30 天。过期记录定期清理。日志只记录来源 ID、错误类别和时间，不记录通知正文。隐私模式开启后，胶囊只显示来源和“新通知”，列表内容需要用户主动打开才呈现。用户可清除单个来源历史或全部历史。未来模块的凭证存储由模块需求独立定义。

## 7. 设置结构

设置页收敛为四组：

1. **外观**：静态内容（未读 / 今日销售额 / 图标）、玻璃浓度、置顶、减少动态、胶囊位置重置。
2. **来源**：已注册来源的状态与启用/停用；模拟通知入口。没有具体来源接入时显示空状态，不提供账号绑定、地址填写或令牌管理。
3. **通知**：各来源的弹出开关、优先级、安静时段、隐私模式、数据保留和清理。
4. **关于**：版本、诊断信息及扩展规范。

首次启动流程：选择静态内容 → 播放模拟通知 → 查看通知列表。旧版本升级时沿用用户当前的销售额首页和原有店铺/凭证设置。来源扩展功能上线后再设计对应的接入引导。

## 8. 技术改造边界

| 现有模块 | 改造方向 |
| --- | --- |
| `core/engine.*`、`core/presentation.mjs` | 保留销售事件处理；新增独立的通用通知校验、持久化和调度器，避免让非销售消息经过金额逻辑 |
| `core/store.cjs` | 新增 `notification_sources`、`notifications`、`notification_state` 表和迁移；旧销售表保持原语义 |
| `electron/application.cjs` | 增加内部来源注册、通知列表 IPC 与窗口状态广播；保持单个胶囊窗口，不新增网络监听服务 |
| `src/App.jsx` | 将品牌固定内容改为可配置静态内容，增加通用通知模板和列表视图 |
| `electron/gerpgo/*`、`electron/custom/*` | 本次不新增适配要求；现有销售逻辑与通用核心保持独立边界 |

所有标准消息先在主进程校验和清洗，渲染进程只接收展示所需字段。扩展模块使用内部契约，不直接操作胶囊窗口、通知数据库或其他来源的状态。

## 9. 验收标准

- 两个模拟来源提交 10 条不同消息后，数据库和列表均保留正确来源、顺序、未读状态；重启后状态不丢失。
- 同一来源重复发送同一 `id` 不重复弹出；另一个来源使用相同 `id` 仍是新通知。
- 连续 20 条低优先级消息被合并/静默后，高优先级消息仍能在当前展示结束后进入胶囊；队列有上限。
- 胶囊从通知内容回到静态状态时没有窗口边界变化、外部色块或误触拖动；Windows 和 macOS 分别验证。
- 安静时段、隐私模式、停用来源和保留期清理均有可重复的行为测试。
- Amazon 新订单仍先展示 SKU 与金额，再回到已更新的销售总额；普通通知不会改变销售额。
- 模拟单个模块异常不阻塞其他来源；历史标记的消息不逐条弹出。
- 使用模拟来源完成验收，无需外部账号、网络请求或具体适配器；文档与 UI 明确区分通用能力与已实现来源。

## 10. 待评审决策

以下选择不阻挡 P0 架构设计，但在视觉稿和开发排期前需要确定：

1. 产品是否更名为通用品牌；若更名，迁移现有用户数据目录与应用标识需单独设计。
2. 首次安装的默认静态内容：本稿建议“未读数量”，升级用户继续使用“今日销售额”。
3. 来源扩展的交付形式：内部模块或未来插件。本稿先采用内部模块契约，插件加载与分发在独立需求中评审。
